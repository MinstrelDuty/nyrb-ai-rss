# 批评深度版书评内容生产设计

日期：2026-09-01

## 1. 目标

在现有“文章 → ChatGPT Scheduled Task → Google Sheet → Markdown/RSS/网页”链路中，提高中文书评介绍的批评深度、事实可靠性和类型适配性。重点不是把文字写得更长，而是让每个判断都能回到原文论点、文本证据和明确的分析框架。

本设计优先服务于“批评深度”：读者应能看出文章主张了什么、凭什么这样主张、它回应了什么问题、哪里仍然有局限。网页和 RSS 继续消费最终 Sheet 行，不新增后端或模型 API。

## 2. 非目标与边界

- 不在 GitHub Actions 中调用 OpenAI、DeepSeek 或其他模型 API。
- 不把网页改造成编辑器或人工审核后台。
- 不要求所有文章都套用“学术史”模板。
- 不为了显得深刻而补写原文没有提供的事实、作者信息或书目信息。
- 旧 DeepSeek 生产 workflow 只有在 Phase 0 通过后才切换；本设计不绕过该门槛。

## 3. 内容生产流程

Scheduled Task 对每篇文章执行两个逻辑阶段，但最终只写一行 Sheet：

### 阶段 A：证据卡

先在内部完成以下判断，不把未经核验的草稿直接发布：

1. `article_type`：`book_review`、`book_list`、`essay`、`obituary`、`poetry`、`film_art`、`news_commentary` 或 `other`。
2. `source_thesis`：用一两句话复述原文的核心判断，不能把自己的联想写成原文观点。
3. `evidence_notes`：列出 2-4 个原文明确出现的细节、例证、概念或叙事转折。
4. `critical_context`：只有在能说明具体关联时，才指出它与某个思想史、学科争论或文学传统的关系。
5. `counterpoint`：指出文章没有处理的反例、盲点、材料限制或可能的另一种解释；如果没有足够依据，明确写“原文未展开”。
6. `confidence`：`high`、`medium` 或 `low`。作者、书名、日期和推荐书目无法确认时降低置信度，不得用猜测填空。

### 阶段 B：面向读者的成稿

根据证据卡写入 `body_markdown`，保留现有字段 `title_zh`、`author_subject`、`hook` 和 `body_markdown`。正文采用以下结构：

```markdown
### 📰 核心脉络
用清晰叙事复述文章如何提出问题、推进论证和得出判断；嵌入 2-4 个证据卡中的具体细节。

### 🧠 批评性分析
先说明文章的分析框架，再说明它与何种具体争论、传统或方法有关；不得只罗列理论名词。

### ⚖️ 张力与限度
指出文章的盲点、证据边界或另一种合理解释。没有依据时写明“原文未展开”，不强行制造反方。

### 📚 延伸阅读
只推荐能确认真实存在、且与本文有明确关系的作品；每项说明关联理由。无法核验时省略该项。
```

`hook` 不再只是重复主题，而应回答“这篇文章最值得读者带走的冲突或判断是什么”，控制在 40-60 个汉字；如果文章是书单，说明书单背后的共同母题，而不是逐本罗列。

## 4. 类型适配

| 类型 | 核心任务 | 批评重点 |
| --- | --- | --- |
| `book_review` | 解释评论者如何评价一本书 | 书的论证、材料、形式与评论者判断之间的张力 |
| `book_list` | 说明书单的选择逻辑 | 编选标准、共同母题、遗漏与读者定位 |
| `essay` | 重建文章的问题意识 | 概念、叙述策略、证据与推论边界 |
| `obituary` | 交代人物及其公共意义 | 生平事实与媒体/制度/时代语境，避免把讣闻写成颂词 |
| `poetry` | 解释意象、声音和形式 | 只做文本细读，不强行套学术史 |
| `film_art` | 描述作品形式及观看框架 | 形式选择、历史语境与评价标准 |
| `news_commentary` | 分清事实、观点和预测 | 证据、利益关系、不确定性和反方解释 |
| `other` | 采用最接近的类型 | 在正文开头说明采用的阅读角度 |

长度只作为软约束：长篇书评约 900-1300 字，短评或书单约 600-900 字；宁可减少空泛段落，也不为了达到字数制造分析。

## 5. 事实与书目核验

- 原文明确写出的信息可以直接复述；模型推断必须使用“可能”“可理解为”等限定语，并放在分析段而非事实段。
- 作者、译者、书名、出版年份和机构名称不能凭常识补全。无法确认时使用“原文未明确”，同时将 `confidence` 降为 `low`。
- 延伸阅读必须先确认书名与作者确实对应，再写推荐理由。不能确认的推荐直接删除，不用“据推测”公开发布。
- 任一关键事实出现冲突时，`status` 写为 `review`，不进入正式 RSS；`verification_note` 记录冲突位置。

## 6. Sheet 字段建议

现有必需字段继续保留：

`source,url,original_title,title_zh,author_subject,hook,body_markdown,article_date,processed_at,image_url,status`

新增可选字段：

`article_type,source_thesis,evidence_notes,critical_context,counterpoint,confidence,verification_note`

第一阶段可只要求 Scheduled Task 可靠填充 `article_type`、`confidence` 和 `verification_note`；其余分析内容进入 `body_markdown`，避免 Sheet 列数量过度膨胀。导入器对旧行使用默认值，保持向后兼容。

## 7. 发布门槛

默认规则：

- `status=published` 且没有关键字段缺失，才进入 Markdown/RSS。
- `confidence=low` 不自动否决，但必须有非空 `verification_note`，并由用户决定是否发布。
- `status=review` 永不进入正式 RSS，只保留在 Sheet 供复核。
- `body_markdown` 中不得出现“未获取中文标题”“根据常见书目推断”等程序占位或未经确认的公开措辞。

自动导入器继续负责机械校验；它不判断观点深度，也不调用模型。内容质量判断由 Scheduled Task 的证据卡和 `status` 完成。

## 8. 评估方法

从 NYT 现有样本中固定抽取至少 6 篇，覆盖单本书评、书单、文化评论、讣闻和短篇/特殊类型。每篇按 0-2 分评估：

1. 核心论点是否清楚；
2. 是否有 2 个以上可回指原文的证据；
3. 批评性分析是否具体而非套话；
4. 是否明确了反方、盲点或不确定性；
5. 作者和书目信息是否可靠；
6. 类型是否匹配写法。

总分 12 分，目标是平均至少 9 分，且“事实可靠性”不得低于 2 分。低于目标的样本不直接发布，先调整提示词或标记人工复核。

## 9. 实施顺序

1. 将本设计转成 Scheduled Task 的统一提示词，保留八来源和 NYT `raw/nyt` 边界。
2. 给导入器增加可选字段解析和 `review` 发布门槛，旧 CSV 继续可导入。
3. 用固定 NYT 样本做新旧输出对照，人工按评分表复核。
4. 通过 Phase 0 后，才把新链路替换为生产 workflow，并废除 DeepSeek 生产调用。
